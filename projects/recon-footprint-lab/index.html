PROJECT 01

Passive OSINT Footprint Lab

WQE7011 Advanced Computer Penetration and Defence · Week-4 lab · 13 Nov 2026

Information asymmetry on a university domain: what an attacker learns without ever sending a packet, and the defensive action each finding implies. Markdown version of this write-up.

Objective

Measure what an attacker can learn about an organisation without ever sending a packet to it (passive reconnaissance only), and turn every finding into a defensive action. The lab uses a public university domain chosen by the lab brief; all sources are public by design (certificate logs, DNS, registry records) or operate on my own data (breach check, sample file metadata).

No scanner, no probing tool and no packets directed at the target were used at any point — every source above is public or self-referential.

Method, step by step

  1. Certificate Transparency search. Queried crt.sh for %.upm.edu.my via the JSON API and collected the hostnames from every logged certificate: 232 unique hostnames. Classified names that suggest internal, test or administrative infrastructure.
  2. DNS and mail records. Ran mx: and dns: lookups. Recorded the mail exchanger priority chain and the name servers.
  3. Registry records. Resolved the domain through ICANN Lookup, which passes .my queries to MYNIC. Recorded registrar, creation and expiry dates, and which registrant fields are redacted.
  4. Breach exposure. Checked my own email address in Have I Been Pwned (the lab rules allow only your own address). Noted the privacy design of the password checker: only the first five characters of a SHA-1 hash leave the device. The API's unauthenticated breach search returned an error response (the v3 API requires a key), so the check was completed through the website interface. My personal results are deliberately excluded from this public repository.
  5. File metadata. Analysed the course sample photo with Metadata2Go and recorded every EXIF field that travels invisibly with the file.

What I would do differently

  • Automate everything from the start. The final approach (crt.sh JSON API via curl + jq) already replaces manual browsing; the same should be done for DNS history and for diffing two CT snapshots over time, where new certificates act as a change detector.
  • Add passive DNS history and SPF/DKIM/DMARC checks. The defender-side controls were derived by hand here; they can be measured directly.
  • Resolve the HIBP API limitation earlier. The unauthenticated breach API returned an error (key required), which cost a round trip before falling back to the website interface.
Scope and ethics. Passive-only: no packets were sent to the target; every source is public by design or self-referential; the breach check used my own address; personal results are excluded from this public repository. The lab target is a public university domain named in the course brief.
